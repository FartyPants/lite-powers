Interview the user relentlessly about the plan, decision or idea at hand until you reach a shared understanding. Use the question rounds in [rounds.md](../brainstorm/rounds.md).

Be relentless: probe assumptions, invent concrete edge-case scenarios that force precision, and check claims against the code. Surface contradictions ("you said X, the code does Y; which is right?").

This is a stress test, not a build. When the frontier is empty, summarize the settled decisions. If a `docs/work/<date>-<topic>/` folder exists for this topic, update its brainstorm.md Decisions section with them. Then ask what the user wants to do next.
